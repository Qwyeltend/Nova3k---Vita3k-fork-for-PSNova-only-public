# Nova3K

Форк эмулятора [Vita3K](https://github.com/Vita3K/Vita3K), заточенный под одну игру — **Phantasy Star Nova** (PS Vita, PCSG00351 / PCSH00143).
Игра в репозиторий не входит: эмулятор запускает собственный дамп игры.

## Сборка

Вкладка **Actions** → *Nova3K Android* → **Run workflow**. С номером версии APK публикуется в **Releases**.
Приложение называется **Nova3K** (`org.nova3k.emulator`) и ставится рядом с обычным Vita3K.

## Что изменено относительно Vita3K

| Изменение | Зачем |
|---|---|
| Имя пакета `org.nova3k.emulator`, название Nova3K | Не конфликтует с установленным Vita3K |
| Только arm64 | Быстрее сборка, x86-Android не нужен |
| ELF-дампы пишутся в `<папка эмулятора>/nova3k/elfdumps/<ID игры>/` | Папку можно открыть файловым менеджером; в Vita3K они лежали в недоступной `Android/data` |
| Своя сборка на GitHub Actions, запуск вручную | Только Android, без лишних платформ |
| Очередь показа кадров: кадр снимается с очереди до вызова функции игры (как до сборки 4080) | Исправляет зависание Nova на чёрном экране перед логотипом SEGA |
| Встроенный патч 60 FPS (включается галочкой **FPS Hack**) | Игра сама ставит себе 30 FPS; патч меняет 30 на 60, предварительно сверив байты |
| Логи шейдеров и дампы текстур в `<папка эмулятора>/nova3k/{shaderlog,textures}` | Доступны для анализа без root |
| Диагностика «текстура из поверхности» в логе (строки `Nova3K:`) | Ищем причину сломанных текстур редактируемого персонажа |
| `sceGxmTransferCopy`/`Downscale` из нарисованной GPU поверхности: эмулятор дожидается копирования, прежде чем рисовать дальше | Игра собирает текстуры кожи/волос/одежды рендером + копированием с `FRAGMENT_SYNC`; без ожидания модель получала недописанную текстуру (разный глитч каждый раз) |
| Копирование из GPU-поверхности при режиме памяти «double-buffer» (по умолчанию): данные сначала переносятся из теневого буфера в память игры | Иначе копировалась старая память, а затем у неё ещё и менялись местами красный/синий — отсюда старые, наполовину старые и «синие» лица/волосы |
| Кэш текстур ставит защиту памяти до чтения текстуры, а не после | Запись, попавшая между чтением и защитой, терялась — текстура оставалась частично старой (чёрные блоки на волосах) |
| Android: показ кадров в режиме FIFO и запрос у системы частоты экрана 60 Гц | Режим Mailbox на экранах 90/120 Гц держал кадры на экране разное время — 60 FPS, но рывками |
| Галочка **V-Sync** теперь видна и для Vulkan: вкл = FIFO, выкл = Mailbox | Сравнить плавность и задержку управления в одной сборке |
| Монитор производительности: раз в секунду строки `Nova3K perf` и `Nova3K threads` в логе; потоки получают понятные имена | Понять, что тормозит: процессор, графика, звук или ожидания |
| Монитор: строка `Nova3K waits` — какие вызовы эмулятора блокировали потоки игры дольше 1 мс; учёт заиканий звука и для SDL | Найти, на чём игра зависает на 70–200 мс несколько раз в секунду |
| Профилировщик: ~1000 раз/с смотрит, где находятся главный поток игры и поток `render` (строки `Nova3K profile`); счётчик ловушек памяти; сборка сохраняет `libVita3K.so` с символами | Понять, что выполняется во время зависаний: переведённый код игры, JIT-компилятор, обработка памяти |
| Монитор: имя ожидаемого семафора/флага в `Nova3K waits`; строка `Nova3K slow frame` для кадров > 50 мс | Разбор каждого медленного кадра главного потока |
| **Dynarmic (патч `tools/nova3k/patches/dynarmic`)**: при создании JIT сбрасывается кэш инструкций только для служебного кода, а не для всех 128 МБ буфера | Каждый новый поток игры стоил десятки миллисекунд — главный источник зависаний |
| ~~Закрепление потоков за большими ядрами~~ — проверено и откачено | Стало хуже: потоки стояли в очереди за 5 большими ядрами 20–35% времени |
| **Dynarmic (патч 0002)** + профилировщик: для выборок в переведённом коде определяется адрес кода игры (строки `Nova3K guest`); статистика JIT раз в секунду (`Nova3K jit`: сколько блоков переведено и за сколько, сколько выброшено и переведено заново из-за ловушек памяти) | Понять, чем именно занят JIT в медленных кадрах: тяжёлой работой игры, ожиданием в цикле или постоянным перепереводом кода |
| **Dynarmic (патч 0003)**: монитор эксклюзивного доступа без глобальной блокировки | Блокировки движка Aska крутятся в цикле до 512 раз на `LDREX/STREX`; в Dynarmic каждая такая инструкция любого потока шла через одну общую спин-блокировку и перебор 150 слотов — потоки толкались на ней. Теперь каждый поток работает со своим слотом, а атомарность обеспечивает сравнение-с-обменом в памяти |
| Ежесекундный отчёт монитора пишется в отдельном потоке `nova3k-report`; профилировщик выключен (`profiler_enabled`) | Отчёт занимал ~60 мс в потоке показа кадров и сам вызывал один пропущенный кадр в секунду |
| Монитор: время главного потока на процессоре и в очереди за свободным ядром в каждом медленном кадре; ядро каждого потока; вызывающая функция для ожиданий в профиле | Проверить, помогло ли закрепление ядер |

## Планы

1. Оставшиеся редкие глитчи текстур персонажа.
2. Онлайн-кооператив через эмуляцию ad-hoc.
3. Свой упрощённый интерфейс под одну игру.
